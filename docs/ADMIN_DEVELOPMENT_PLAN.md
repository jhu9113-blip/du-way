# DU WAY 관리자 페이지 개발 계획

> 기준 시점: 2026-08-12<br>
> 대상: 현재 DU WAY 목업 프로토타입<br>
> 관리자 계정: 단일 하드코딩 계정 `admin` / `admin`

## 1. 목적

관리자 페이지는 현재 사용자 앱에서 사용하는 캠퍼스 목업 데이터를 한곳에서 확인하고, 발표 중 필요한 데이터와 예외 상태를 간단히 관리하기 위한 내부용 화면이다.

일반 사용자는 로그인이나 회원가입 없이 기존 앱을 그대로 이용한다. 관리자만 `/admin` 진입 시 단일 계정으로 인증한다. 관리자 계정 추가, 권한 분리, 사용자 관리는 구현하지 않는다.

## 2. 기본 원칙

- 일반 사용자 앱에는 로그인·회원가입·인증 화면을 추가하지 않는다.
- 관리자 계정은 하나만 제공하며 아이디와 비밀번호는 각각 `admin`, `admin`으로 고정한다.
- 관리자 회원가입, 계정 생성·수정·삭제, 비밀번호 변경·찾기 기능은 만들지 않는다.
- 역할별 권한, 메뉴별 권한, 승인 절차는 만들지 않는다.
- 데이터베이스, 서버 API, 외부 API, 지도 SDK, `localStorage`는 사용하지 않는다.
- 관리자에서 수정한 값은 React 메모리 상태에만 반영하며 새로고침하면 초기 목업으로 돌아간다.
- 경로를 자동 계산하지 않고 기존 `FAST`, `ACCESSIBLE` 목업 값을 수정·미리보기만 한다.
- 관리자 페이지는 운영 보안이 적용된 실제 백오피스가 아니라 발표용 프로토타입이다.

### 하드코딩 인증의 한계

`admin / admin`을 클라이언트 코드에서 비교하는 방식은 실제 보안을 제공하지 않는다. 소스와 브라우저 개발자 도구에서 자격 증명을 확인하거나 인증 상태를 우회할 수 있으므로 실제 서비스에 배포할 관리자 인증으로 사용해서는 안 된다. 현재 단계에서는 관리자 화면 진입 흐름을 시연하는 용도로만 사용한다.

## 3. 포함 기능

### 3.1 관리자 로그인

- `/admin/login`에서 아이디와 비밀번호 입력
- `admin / admin`이 모두 일치하면 관리자 대시보드로 이동
- 불일치하면 한국어 오류 문구 표시
- 로그인 상태는 관리자 전용 Context의 메모리 상태로 유지
- 로그아웃 시 로그인 상태를 해제하고 `/admin/login`으로 이동
- 새로고침하면 로그인 상태가 초기화되어 다시 로그인
- 로그인되지 않은 상태로 관리자 하위 화면에 접근하면 로그인 화면으로 전환

로그인 화면에는 회원가입, 비밀번호 찾기, 소셜 로그인 링크를 표시하지 않는다.

### 3.2 관리자 대시보드

- 등록된 건물 수
- 등록된 접근성 시설 수와 타입별 개수
- 빠른 경로·무장애 경로 요약
- 등록된 데모 수업 수
- GPS 실패·경로 없음 시연 상태
- 건물, 시설, 경로, 수업 관리 화면으로 이동하는 바로가기
- 현재 데이터가 새로고침 시 초기화되는 목업임을 알리는 안내

별도 차트, 사용자 통계, 접속 통계, 실시간 모니터링은 제공하지 않는다.

### 3.3 건물 관리

- 건물 4개 목록 조회
- 건물명, 별칭, 위도, 경도 수정
- 출입구 노드 ID 수정
- 실내 진입 안내 수정
- 건물별 상세 화면 또는 편집 패널
- 필수값과 위도·경도 숫자 형식 검증
- 사용자 앱 지도에서 수정 결과 미리보기
- 현재 목업 초기값으로 되돌리기

현재 시연 동선이 기존 건물 ID에 의존하므로 MVP에서는 건물 추가·삭제와 ID 변경을 지원하지 않는다.

### 3.4 접근성 시설 관리

- 시설 6개 목록 조회
- 시설 타입별 필터
- 시설명, 타입, 위치, 연결 건물, 설명 수정
- 지도에서 시설 위치와 기호 미리보기
- 필수값과 좌표 형식 검증
- 현재 목업 초기값으로 되돌리기

MVP에서는 시설 사진, 고장 이력, 점검 일정, 담당자 정보와 사용자 제보를 관리하지 않는다. 시설 추가·삭제도 제외하고 기존 목업 편집에 집중한다.

### 3.5 경로 관리

- 빠른 경로와 무장애 경로 목록 및 선택
- 거리, 예상 시간, 계단·엘리베이터·경사로 수 수정
- 급경사 포함 여부와 경고 문구 수정
- 경로 노드 목록 조회
- 노드의 위도·경도와 타입 수정
- `MapCanvas`를 재사용한 실선·파선 경로 미리보기
- 수정 전 기본 경로로 되돌리기

MVP에서는 지도 위 드래그 편집, 신규 경로 생성, 출발지·목적지 조합 추가와 자동 경로 계산을 제외한다.

### 3.6 데모 수업 및 고정 안내값 관리

- 현재 월요일 수업 2개 조회
- 수업명, 시간, 건물, 강의실 수정
- 다음 수업과 출발지에 사용되는 고정 안내값 확인
- 추천 출발 10:14, 예상 이동 13분, 부족 시간 3분 등의 시연값 수정
- 사용자 홈과 시간표에서 표시될 결과 미리보기
- 초기 목업 값으로 되돌리기

수업 추가·삭제, 학생별 시간표, 학사 시스템 연동은 제외한다.

### 3.7 시연 상태 관리

- GPS 실패 상태 켜기·끄기
- 경로 없음 상태 켜기·끄기
- 사용자 길안내 화면에서 결과 확인 링크
- 모든 시연 상태 초기화

기존 `/settings`의 시연 토글과 같은 상태를 사용해 관리자와 사용자 화면의 결과가 일치하도록 한다.

## 4. 제외 기능

현재 프로토타입에서 필요성이 낮거나 백엔드 없이는 의미가 작은 다음 기능은 구현하지 않는다.

- 일반 사용자 로그인 및 회원가입
- 관리자 회원가입, 계정 관리, 다중 관리자
- 역할·권한 설정과 승인 워크플로
- 비밀번호 변경·찾기와 로그인 기록
- 사용자 목록과 개인 시간표 조회
- 공지사항 관리
- 사용자 제보 접수·처리
- 접속자·이용률·오류 통계와 차트
- 공사 일정과 시설 고장 이력 관리
- 파일·이미지 업로드
- 데이터 가져오기·내보내기와 일괄 업로드
- 변경 이력, 버전 비교, 되돌리기 기록
- 데이터베이스·서버 저장과 외부 서비스 연동

필요해질 경우 실제 인증과 데이터 저장 구조를 먼저 설계한 뒤 별도 범위로 추가한다.

## 5. 라우트 구조

```text
/admin/login             관리자 로그인
/admin                   대시보드
/admin/buildings         건물 관리
/admin/facilities        접근성 시설 관리
/admin/routes            경로 관리
/admin/demo              수업·고정 안내값·시연 상태 관리
```

관리자 화면은 사용자용 하단 탭을 표시하지 않고 별도의 관리자 헤더와 메뉴를 사용한다. 모바일에서도 사용할 수 있게 만들되, 데이터 편집 화면은 태블릿·PC 폭을 우선한다.

## 6. 상태 구조 제안

관리자 인증과 편집용 데이터는 사용자 앱 상태와 구분하되, 편집 완료 결과는 사용자 미리보기에서 함께 읽을 수 있어야 한다.

```ts
type AdminState = {
  authenticated: boolean
}

type EditableDemoState = {
  buildings: Building[]
  facilities: Facility[]
  routes: Record<'FAST' | 'ACCESSIBLE', RouteResult>
  courses: Course[]
  demo: DemoValues
}
```

- `AdminState`는 관리자 진입 여부만 관리한다.
- 편집 상태는 초기값을 `data/mock.ts`와 `lib/demo.ts`에서 복제해 시작한다.
- 화면 간 이동 중에는 수정값을 유지한다.
- 새로고침 또는 전체 초기화 시 원본 목업으로 돌아간다.
- 기존 사용자 앱이 파일 상수를 직접 읽는 구조는 관리자 수정값을 반영할 수 있도록 Context 기반 조회로 단계적으로 정리한다.

## 7. 개발 단계

### 1단계 — 관리자 셸과 단일 계정 인증

- `/admin/login` 구현
- `admin / admin` 비교와 오류 상태 구현
- 관리자 전용 레이아웃·메뉴·로그아웃 구현
- 비인증 관리자 라우트 보호
- 사용자 하단 탭이 관리자 화면에 나타나지 않도록 레이아웃 분리

완료 조건:

- 일반 사용자 앱은 인증 없이 계속 사용할 수 있다.
- 올바른 단일 계정으로만 관리자 화면에 진입한다.
- 로그아웃과 새로고침 후 다시 로그인이 필요하다.

### 2단계 — 관리자 대시보드와 편집 상태

- 건물·시설·경로·수업 요약 카드 구현
- 편집용 목업 Context와 초기화 액션 구현
- 사용자 앱과 관리자 미리보기가 같은 편집 상태를 읽도록 연결
- 메모리 전용 데이터라는 안내 표시

완료 조건:

- 대시보드 수치가 현재 편집 상태와 일치한다.
- 페이지 이동 중 변경값이 유지되고 새로고침 시 초기화된다.

### 3단계 — 건물과 시설 관리

- 목록, 필터, 편집 폼, 유효성 검사 구현
- `MapCanvas` 미리보기 연결
- 항목별 초기화 구현

완료 조건:

- 건물·시설 수정 결과가 지도와 사용자 미리보기에 즉시 반영된다.
- 잘못된 좌표와 빈 필수값은 적용되지 않는다.

### 4단계 — 경로 관리

- 경로 요약값과 경고 편집
- 노드 좌표·타입 편집
- 빠른 파선·무장애 실선 미리보기
- 경로별 초기화 구현

완료 조건:

- 수정한 거리·시간·위험 정보와 노드가 길안내 미리보기에 일치한다.
- 경로 계산이나 외부 지도 호출이 발생하지 않는다.

### 5단계 — 데모 데이터와 시연 상태 관리

- 수업 2개와 홈 고정 안내값 편집
- GPS 실패·경로 없음 토글 연결
- 사용자 홈·시간표·길안내 확인 링크 제공
- 전체 데모 초기화 구현

완료 조건:

- 관리자에서 변경한 값이 사용자 화면에 동일하게 표시된다.
- 예외 상태를 켜고 끌 때 길안내 화면이 정상적으로 전환된다.

### 6단계 — 통합 검증

- 관리자 로그인 → 데이터 편집 → 사용자 미리보기 → 초기화 흐름 검증
- 375px과 1280px 레이아웃 확인
- 키보드 조작, 포커스, 레이블, 오류 안내 확인
- ESLint, TypeScript, production build 실행
- 일반 사용자 앱의 기존 시연 흐름 회귀 확인

## 8. 인수 시나리오

### A-01 관리자 진입

1. 일반 사용자 앱이 로그인 없이 열리는지 확인한다.
2. `/admin` 직접 접근 시 `/admin/login`으로 이동하는지 확인한다.
3. 잘못된 계정으로 오류 문구를 확인한다.
4. `admin / admin`으로 로그인해 대시보드에 진입한다.
5. 로그아웃 후 관리자 화면에 다시 접근할 수 없는지 확인한다.

### A-02 데이터 편집과 미리보기

1. 건물 실내 안내와 시설 설명을 수정한다.
2. 경로의 거리, 경고 또는 노드 좌표를 수정한다.
3. 관리자 지도와 사용자 길안내 화면에 같은 값이 표시되는지 확인한다.
4. 초기화 후 원본 목업 값으로 복구되는지 확인한다.

### A-03 시연 상태 제어

1. 관리자에서 GPS 실패를 켜고 사용자 길안내의 대체 안내를 확인한다.
2. 경로 없음을 켜고 대체 화면을 확인한다.
3. 모든 시연 상태를 초기화하고 정상 길안내로 복구한다.

### A-04 비영속성

1. 관리자에서 데이터를 수정한다.
2. 관리자 메뉴와 사용자 화면 사이를 이동하며 값이 유지되는지 확인한다.
3. 전체 새로고침 후 로그인과 편집값이 초기화되는지 확인한다.

## 9. 완료 기준

- 일반 사용자는 로그인 없이 기존 5개 화면을 사용할 수 있다.
- 관리자 계정은 `admin / admin` 하나뿐이다.
- 회원가입, 계정 관리, 권한 설정 화면이 존재하지 않는다.
- 건물, 시설, 두 경로, 수업과 시연 상태를 관리자에서 확인·수정·초기화할 수 있다.
- 수정 결과가 현재 브라우저 세션의 사용자 미리보기에 반영된다.
- 새로고침 시 관리자 인증과 편집값이 초기화된다.
- 외부 API, 지도 SDK, 데이터베이스, 실제 경로 계산을 사용하지 않는다.
- 기존 사용자 앱의 정상·GPS 실패·경로 없음 흐름이 유지된다.
- ESLint, TypeScript와 production build가 통과한다.
