# DU WAY 개발 계획

## 1. 문서 목적

이 문서는 `docs/PRD.md`를 기준으로 DU WAY 프로토타입을 순차 개발하기 위한 실행 계획이다. 개발은 스프린트 단위로 진행하며, 각 스프린트가 끝날 때 독립적으로 검토 가능한 결과물을 만든다.

최종 성공 기준은 발표 환경에서 온보딩부터 홈, 시간표, 길안내, 설정까지 5개 화면이 끊김 없이 연결되고, 사용자의 이동 조건과 주요 예외 상황이 한국어 UI로 명확하게 표현되는 것이다.

> 기준 시점: 2026-08-11  
> 기술 기준: 저장소에 설치된 Next.js 16.3.0(App Router), React 19, TypeScript, Tailwind CSS 4, shadcn/ui  
> 참고: PRD에는 Next.js 15가 명시되어 있으나 실제 구현과 검증은 설치된 Next.js 16.3.0 및 `node_modules/next/dist/docs/`의 가이드를 기준으로 한다.

## 2. 제품 범위

### 2.1 포함 범위

- 이동 조건만 수집하는 온보딩
- 다음 수업, 출발 권장 시각, 연강 경고를 보여주는 홈
- 월요일 데모 시간표와 다음 수업 표시
- 빠른 경로와 무장애 경로의 비교 및 SVG 지도 표시
- 이동 수단, 경로 우선순위, 도착 여유 시간 설정
- GPS 실패 및 조건에 맞는 경로 없음 상태 시연
- 5개 라우트 간 하단 탭 탐색
- 모바일 우선 반응형 화면과 키보드·스크린 리더 접근성
- 파일에 정의한 목업 데이터와 React Context/useReducer 기반 세션 상태

### 2.2 제외 범위

- 데이터베이스, 서버 API, 외부 API 및 지도 SDK
- 회원가입, 로그인, 인증 및 개인식별정보 입력
- `fetch`, `axios`, `localStorage`를 포함한 데이터 연동·영속화
- 실제 GPS 연동 및 실제 경로 계산 알고리즘
- 시간표 추가·수정·삭제 UI
- 운영 배포를 위한 실측 좌표 확정 및 백엔드 구축

제외 범위의 기능은 프로토타입 안에서 유사 구현하지 않는다. 경로와 시간 관련 값은 PRD의 고정 목업 값을 그대로 사용한다.

## 3. 핵심 사용자 흐름

1. 사용자가 `/onboarding`에서 이동 수단과 경로 선호 조건을 선택한다.
2. 시작하기를 누르면 상태가 갱신되고 홈(`/`)으로 이동한다.
3. 홈에서 다음 수업, 추천 출발 시각, 예상 이동시간, 연강 경고와 지도 미리보기를 확인한다.
4. 시간표(`/timetable`)에서 다음 수업을 확인하고 길안내로 이동한다.
5. 길안내(`/route`)에서 무장애 경로와 빠른 경로를 전환하고 거리·시간·위험 요소·실내 진입 안내를 확인한다.
6. 설정(`/settings`)에서 이동 조건과 여유 시간을 변경하고 예외 상황을 재현한다.
7. 하단 탭으로 주요 화면을 이동하며 변경한 상태가 현재 브라우저 세션 동안 유지된다.

## 5. 개발 원칙

- App Router의 페이지·레이아웃 규칙을 따른다.
- Context Provider와 상호작용 컴포넌트만 Client Component 경계에 두고, 불필요하게 클라이언트 범위를 넓히지 않는다.
- 상태는 `lib/store.tsx`의 `useAppState()`와 `useAppDispatch()`로만 읽고 변경한다.
- 타입은 `types/index.ts`, 목업 원본은 `data/mock.ts`, 시연 고정 표현값은 한곳에서 관리한다.
- 지도 교체 가능성을 보장하기 위해 `MapCanvas`의 PRD props 인터페이스를 변경하지 않는다.
- 색상만으로 의미를 전달하지 않고 아이콘, 선 모양, 텍스트를 함께 사용한다.
- 각 기능은 정상 상태뿐 아니라 빈 상태·실패 상태·키보드 조작을 함께 검증한다.
- PRD 범위를 넘어서는 기능은 별도 백로그로 분리하고 현재 스프린트에 끼워 넣지 않는다.

## 6. 스프린트 계획

스프린트는 1주 단위를 권장한다. 팀 여건에 따라 기간을 조정하더라도 아래 순서와 선행 조건은 유지한다.

### Sprint 0 — 기반 점검과 요구사항 고정

**목표:** 이후 화면 개발이 의존할 타입, 데이터, 상태, 라우트 뼈대를 안정화한다.

**작업**

- 실제 설치 버전과 Next.js 로컬 문서 기준 확인
- PRD 타입과 `types/index.ts`의 필드 일치 여부 점검
- 건물·시설·경로·수업·설정·데모 시각 목업 검증
- Context, reducer, Provider, 전용 훅과 액션 목록 검증
- 5개 라우트 및 공통 컴포넌트 구조 확인
- `fetch`/`axios`/`localStorage`/지도 SDK와 개인정보 필드가 없음을 정적 검색으로 확인
- lint 및 production build 기준선 확보

**산출물**

- 검증된 `types/index.ts`, `data/mock.ts`, `lib/store.tsx`
- 공통 레이아웃, 하단 탭, `MapCanvas` 및 5개 라우트 뼈대
- 발견된 PRD 대비 차이와 후속 작업 목록

**완료 조건**

- PRD의 타입 필드가 추가·삭제되지 않았다.
- 초기 상태가 PRD의 값과 일치한다.
- 앱이 빌드되고 5개 URL이 모두 렌더링된다.
- 금지 기술이 코드에 포함되지 않는다.

### Sprint 1 — 공통 셸과 온보딩

**목표:** 첫 진입부터 홈 진입까지의 흐름과 전체 화면 탐색 기반을 완성한다.

**작업**

- 한국어 메타데이터, 모바일 viewport, 최대 폭 중앙 정렬 레이아웃 확정
- 온보딩에서 이동 수단 4종과 경로 선호 4종 선택 구현
- 시작하기 시 설정 저장 및 `onboarded` 변경 후 홈 이동
- 미완료 사용자의 홈 접근을 온보딩으로 전환
- 온보딩에서는 하단 탭을 숨기고 나머지 화면에서는 표시
- 하단 탭 활성 상태, `aria-current`, 44px 이상 조작 영역 검증
- 새로고침하면 초기화되는 비영속 상태임을 확인

**완료 조건**

- 개인정보를 입력하는 필드가 없다.
- 모든 선택 항목을 키보드로 조작할 수 있고 선택 상태가 텍스트/아이콘과 접근성 속성으로 전달된다.
- 온보딩 완료 후 홈으로 이동하며 탭을 통한 4개 주요 화면 이동이 가능하다.

### Sprint 2 — 홈 대시보드

**목표:** 발표자가 다음 수업과 출발 필요성을 한 화면에서 설명할 수 있게 한다.

**작업**

- 다음 수업 `UX 디자인`, 10:30, 경상대학 1402호 카드 구현
- 출발지 성산홀, 예상 이동 13분, 추천 출발 10:14 표시
- 직전 수업 종료와 이동시간을 근거로 3분 부족 연강 경고 표시
- 무장애 경로 지도 미리보기와 목적지 강조
- 길안내 시작 및 오늘 시간표 이동 CTA 구현
- 숫자와 경고 문구가 계산 결과가 아닌 고정 시연값을 사용하는지 검증

**완료 조건**

- PRD의 고정값이 정확히 노출된다.
- 경고가 색상 외에 아이콘, 제목, 설명으로 전달된다.
- 홈의 두 CTA가 올바른 라우트로 이동한다.

### Sprint 3 — 시간표와 지도 컴포넌트

**목표:** 수업 맥락과 캠퍼스 공간 정보를 재사용 가능한 UI로 완성한다.

**작업**

- 월요일 수업을 시간순으로 표시하고 다음 수업을 명시
- 다음 수업 카드에서 길안내로 이동하는 동선 구현
- `MapCanvas` 좌표 bounding box 및 SVG 정규화 투영 검증
- 건물 4개, 시설 6개, 시설별 아이콘과 `aria-label` 표시
- 무장애 실선/빠른 경로 파선, 워터마크, 목적지 강조 구현
- 현재 위치 점과 정확도 원, 건물 클릭·키보드 이벤트 검증
- 좌표가 없거나 한 축의 범위가 0인 경우 안전한 렌더링 확인

**완료 조건**

- 시간표의 수업명, 시간, 장소가 목업과 일치한다.
- 두 경로가 색상을 보지 않아도 선 모양으로 구별된다.
- 지도는 전달받은 props만 사용하며 외부 SDK나 API를 호출하지 않는다.

### Sprint 4 — 길안내 상세

**목표:** 빠른 경로와 무장애 경로의 차이를 사용자가 명확히 비교할 수 있게 한다.

**작업**

- 무장애 경로를 기본 선택으로 제공하고 두 경로 전환 UI 구현
- 거리, 예상 시간, 계단 수 지표 표시
- 빠른 경로의 계단 1곳·급경사 1곳 경고 표시
- 무장애 경로의 엘리베이터 1곳·경사로 1곳 및 안전 상태 표시
- 경상대학 실내 진입 안내 표시
- 탭 역할, 선택 상태, 키보드 포커스 및 스크린 리더 레이블 검증

**완료 조건**

- FAST는 620m/8분, ACCESSIBLE은 760m/11분으로 목업 값이 표시된다.
- 경로를 전환할 때 지도, 요약, 경고, 시설 안내가 함께 바뀐다.
- 위험 정보는 아이콘과 구체적인 텍스트를 포함한다.

### Sprint 5 — 설정과 예외 상태

**목표:** 설정 변경과 발표 중 실패 시나리오를 끊김 없이 재현한다.

**작업**

- 이동 수단 4종과 경로 우선순위 4종 편집
- 도착 여유 시간을 0~30분 범위에서 1분 단위로 조절
- 값 변경을 전역 상태에 즉시 반영
- GPS 실패 토글과 사용자 안내 상태 구현
- 경로 없음 토글과 길안내 대체 상태 구현
- 실패 상태 해제 시 정상 화면 복구 검증
- 설정이 경로를 실제 계산하는 것처럼 오인시키지 않도록 문구 정리

**완료 조건**

- 설정값이 페이지 이동 후에도 현재 세션 내에서 유지된다.
- 버퍼 값이 범위를 벗어나지 않는다.
- GPS 실패와 경로 없음 상태 각각에 문제 설명과 사용자가 취할 다음 행동이 제공된다.
- 어떤 예외 상태에서도 탐색이 막히지 않는다.

### Sprint 6 — 접근성, 회귀 검증, 발표 준비

**목표:** 전체 기능을 통합 검증하고 발표 가능한 릴리스 후보를 만든다.

**작업**

- 375px, 중간 폭, 1280px 화면의 레이아웃 점검
- 본문 16px, 44×44px 터치 영역, 대비 4.5:1 이상 확인
- Tab/Shift+Tab/Enter/Space만으로 핵심 흐름 수행
- 포커스 링, 제목 구조, landmark, 레이블, 상태 알림 검토
- 온보딩 → 홈 → 시간표 → 길안내 → 설정 → 예외 복구 회귀 테스트
- 금지 기술과 개인정보 필드 재점검
- lint, TypeScript, production build 실행
- 발표용 데모 순서와 초기 상태 복원 절차 문서화

**완료 조건**

- 아래 핵심 인수 시나리오가 모두 통과한다.
- 치명적·주요 결함이 0건이고 경미한 결함은 발표에 미치는 영향과 우회 방법이 기록되어 있다.
- 프로덕션 빌드가 성공하며 브라우저 콘솔 오류가 없다.

## 7. 핵심 인수 시나리오

### A-01 첫 사용자 흐름

1. 초기 상태에서 홈에 접근한다.
2. 온보딩으로 이동되는지 확인한다.
3. 수동 휠체어, 계단 피하기, 완만한 경사 우선을 선택한다.
4. 시작하기를 누른다.
5. 홈에서 선택한 이동 수단과 고정된 다음 수업 정보가 보이는지 확인한다.

### A-02 다음 수업 길안내

1. 홈에서 10:14 추천 출발과 13분 예상 이동을 확인한다.
2. 3분 부족 연강 경고를 확인한다.
3. 길안내 시작하기를 누른다.
4. 무장애 경로 760m, 11분, 계단 0곳을 확인한다.

### A-03 시간표 연계

1. 하단 탭에서 시간표로 이동한다.
2. 수업 2개가 시간순으로 표시되는지 확인한다.
3. UX 디자인이 다음 수업으로 표시되는지 확인한다.
4. 해당 카드의 길안내 버튼으로 `/route`에 진입한다.

### A-04 예외 복구

2. 관련 화면에서 실패 안내와 대체 행동을 확인한다.

### A-05 접근성 탐색

## 9. 공통 완료 정의(Definition of Done)

각 스프린트의 작업은 다음 조건을 모두 만족해야 완료로 본다.

- 해당 요구사항과 인수 조건이 충족되었다.
- TypeScript 오류, lint 오류, 브라우저 콘솔 오류가 없다.
- 신규 인터랙션을 키보드로 조작할 수 있고 포커스가 보인다.
- 사용자에게 보이는 모든 문구가 자연스러운 한국어다.
- 375px 및 1280px에서 내용 잘림과 조작 방해가 없다.
- 목업 데이터, 고정 시연값, 외부 연동 금지 원칙을 위반하지 않는다.
- 변경으로 영향을 받는 기존 핵심 사용자 흐름을 다시 확인했다.
- 구현과 PRD가 달라진 경우 문서에 결정 근거가 기록되었다.

## 12. 현재 구현 기준 착수 메모

저장소에는 타입, 목업 데이터, Context 상태, 공통 레이아웃, 하단 탭, SVG 지도와 5개 화면의 주요 UI가 이미 존재한다. 따라서 실제 착수 시 Sprint 0에서 각 항목을 단순히 다시 만드는 대신 PRD와 대조하여 다음 세 상태로 분류한다.

- **완료:** 요구사항과 인수 조건을 충족하며 검증만 필요한 항목
- **보완:** UI는 있으나 예외 상태, 접근성 또는 값 연계가 부족한 항목
- **신규:** 아직 사용자 흐름에 연결되지 않은 항목

특히 `demoGpsFailed`는 상태와 설정 토글이 존재하더라도 소비 화면의 실패 안내까지 연결되었는지를 Sprint 5에서 확인해야 한다. 현재 구현된 화면은 최종 완료로 간주하지 않고 각 스프린트의 완료 조건을 통과한 뒤 완료 처리한다.
