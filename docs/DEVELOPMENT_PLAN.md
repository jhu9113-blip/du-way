## 1. 목적

이 문서는 초기 스프린트 계획이 아니라 현재 코드 기준의 구현 현황과 남은 검증 작업을 추적한다. 제품 요구사항과 고정값은 `docs/PRD.md`, 발표 순서는 `docs/DEMO_GUIDE.md`를 기준으로 한다.

Next.js 관련 변경 시에는 저장소의 `node_modules/next/dist/docs/01-app/` 가이드를 먼저 확인한다.

## 3. 구현 구조

```text
types/index.ts ──┐
data/mock.ts ────┼─> lib/store.tsx ─> 각 Client Page
lib/demo.ts ─────┘                    │
                                     ├─> 공통 헤더·하단 탭·토글
                                     └─> MapCanvas
```

- `app/layout.tsx`: 한국어 메타데이터, viewport, 폰트, Provider, 공통 하단 탭, production Analytics
- `lib/store.tsx`: 설정·수업·데모 상태와 reducer 액션
- `lib/demo.ts`: 홈 고정값, 라벨, 건물 조회, 거리·시간 표시 함수
- `data/mock.ts`: 건물 4개, 시설 6개, 수업 2개, 경로 2종
- 페이지: 온보딩, 홈, 시간표, 길안내, 설정

## 4. 확인된 구현 결정

- PRD 초안의 Next.js 15 대신 실제 설치 버전인 16.3.0을 사용한다.
- 상태는 영속화하지 않으며 전체 새로고침 시 초기화된다.
- 설정 화면은 경로와 시간이 고정된 시연값임을 명시한다.
- 홈의 예상 이동 13분과 경로 상세의 8분·11분은 서로 다른 목적의 고정 표시값이다.
- 미완료 사용자의 자동 온보딩 전환은 현재 홈(`/`)에만 구현되어 있다. `/timetable`, `/route`, `/settings` 직접 접근은 허용된다.
- 경로 없음 상태가 GPS 실패보다 우선하여 전체 대체 화면을 표시한다.
- Vercel Analytics는 production 환경에서만 렌더링된다. 이는 사용자 기능용 데이터 API나 경로 계산 연동이 아니다.

## 5. 남은 검증 작업

### 정적·빌드 검증

- `pnpm lint`
- `pnpm exec tsc --noEmit`
- `pnpm build`
- 앱 코드에서 `fetch`, `axios`, `localStorage`, 지도 SDK 사용 여부 검색
- 개인정보 입력 필드 존재 여부 검색

Windows PowerShell 실행 정책이 `pnpm.ps1`을 막는 환경에서는 동일한 명령을 `pnpm.cmd`로 실행한다.

### 브라우저 검증

- 375px와 1280px에서 잘림, 겹침, 하단 탭 가림 확인
- 온보딩 → 홈 → 시간표 → 길안내 → 설정 흐름 확인
- Tab, Shift+Tab, Enter, Space와 경로 탭의 방향키/Home/End 확인
- 200% 확대, 포커스 가시성, 텍스트 대비 4.5:1 확인
- 화면 낭독기로 제목, 현재 탭, 경고, 지도와 시설 레이블 확인
- 브라우저 콘솔 오류 확인

## 6. 인수 시나리오

### A-01 정상 흐름

1. `/onboarding`을 새로고침한다.
2. 수동 휠체어, 계단 피하기, 완만한 경사 우선을 선택한다.
3. 시작하기 후 홈에서 UX 디자인, 10:14, 13분, 3분 부족을 확인한다.
4. 시간표에서 수업 2개와 다음 수업을 확인한다.
5. 길안내에서 무장애 760m·11분과 빠른 620m·8분을 비교한다.

### A-02 예외 복구

1. 설정에서 GPS 실패를 켜고 길안내의 성산홀 기준 안내를 확인한다.
2. 설정으로 돌아가 GPS 실패를 끈다.
3. 경로 없음을 켜고 길안내의 대체 화면과 설정 링크를 확인한다.
4. 토글을 끈 뒤 정상 경로로 복구되는지 확인한다.

### A-03 비영속 상태

1. 설정값과 예외 토글을 변경한다.
2. 탭 이동 중 값이 유지되는지 확인한다.
3. 전체 새로고침 후 초기값으로 돌아가는지 확인한다.
